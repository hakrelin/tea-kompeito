Nginx 配置的几个习惯

2026-10-24Nginx / 运维

一台机器上放多个站点之后，配置散在主文件里改起来最容易出事。下面几条是踩过坑之后固定下来的做法。

1. 站点配置全部拆到 conf.d

主文件只留全局参数，站点一个域名一个文件：

# /etc/nginx/nginx.conf
http {
    include       mime.types;
    sendfile      on;
    keepalive_timeout 65;
    server_tokens off;
    client_max_body_size 128m;

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;

    include /etc/nginx/conf.d/*.conf;
}

注意 conf.d 里要有一个显式的 default_server，否则直接用 IP 或未绑定的 Host 访问时，落到的会是文件名排序最前的那个 server，排查起来很费劲。

2. 改完先 nginx -t，再 reload

nginx -t && systemctl reload nginx

reload 是平滑重载，已有连接不断；restart 会直接断掉。另一个容易误判的点：reload 失败时旧进程照旧在跑，站点看起来"没事"，以为自己改对了。用 nginx -T 打印当前实际加载的完整配置来核对，比看文件可靠。

3. PHP 段别漏 SCRIPT_FILENAME

location ~ \.php$ {
    try_files $uri =404;
    fastcgi_pass unix:/run/php-fpm/www.sock;
    fastcgi_index index.php;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_read_timeout 120;
}

两条经验：

  • 少了 SCRIPT_FILENAME，现象不是 502，而是 php-fpm 返回 File not found.，很容易误判成路径问题。
  • try_files $uri =404; 不能省，否则不存在的 .php 会被直接丢给 fastcgi。

4. 隐藏版本号

server_tokens off;

错误页里不再带 nginx/1.30.6。只是减少一点无差别扫描的噪音，不算安全措施。

5. 源码装的 nginx 要自己配日志轮转

发行版包会带 logrotate 配置，编译安装的不会，日志会一直涨：

/www/wwwlogs/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    create 0640 nginx nginx
    postrotate
        [ -f /run/nginx.pid ] && kill -USR1 $(cat /run/nginx.pid)
    endscript
}

USR1 才是"重开日志文件"，HUP 是"重载配置"。写错成 HUP 的话，轮转一次就重载一次配置，出问题时很难想到是这里。

6. 上传大小默认只有 1m

client_max_body_size 128m;

放到 http 或具体 server 段都行。现象是 413 Request Entity Too Large，跟 PHP 的 upload_max_filesize 是两回事，两边都要改。

检查清单

  • nginx -t 通过
  • nginx -T | grep server_name 能对上站点
  • 日志文件有写入、有轮转
  • 默认站点是预期的那个
